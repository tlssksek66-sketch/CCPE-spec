# CCPE v0.1.5 — Workbook-Scope Limits + Verify Discipline + Contract Label

**Release date**: 2026-05-08
**Theme**: Workbook-wide constraints + verification rigor + label class extension

## What's new

**Three patterns promoted** from active operational case (V20 trial):

### Hard limits (workbook scope)
- **#8 Workbook Cell Cap Silent Overflow** — 10 M cells per workbook
  (distinct from per-sheet #4)

### Verify discipline
- **#9 requireNonEmpty Guard Missing** — false-positive ok=true on empty sheets

### Positive contracts (NEW label class)
- **#10 Cleanup Idempotent Contract** — guarantees, not limitations
  (label discipline introduced)

### Deferred to v0.1.6 (queued)

The following operational queue patterns surfaced during V20 trial but
require additional case derivation before promotion:

- Dual-source defect (hardcoded constants ↔ data file drift) — observed
  in V20 G1-finalize (EXPECTED_ROWS hardcoded ↔ inventory.csv)
- Verify-only wrapper pattern — separation of reload from verification
- DriveApp.setContent metafile refresh pattern

These will be promoted in v0.1.6 with full case derivation per #8/#9/#10
template.

## Why three patterns + contract label in one release

Three closely-related discoveries from a single trial cluster:
1. **Limit / detection** (#8, #9) — surface-level platform behavior
2. **Discipline / contract** (#10) — operational hygiene + new label class

Splitting these would inflate minor releases without meaningful boundary;
v0.1.6 will carry the operational queue cluster separately.

## Label discipline change

v0.1.5 introduces the `contract` label class alongside existing `quirk` /
`anti-pattern` classes. Operators reading APPENDIX must interpret labels:
- `quirk` → platform behavior to work around
- `anti-pattern` → don't do this
- `contract` → guarantee to rely on (NEW)

## Migration

APPENDIX expanded: #1, #4, #5, #7 → +#8, #9, #10 (label-mixed: 2 quirks +
1 contract).
