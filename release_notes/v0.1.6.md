# CCPE v0.1.6 — Self-Application + Broad-Verify Promotion + Automation Infra

**Release date**: 2026-05-16
**Theme**: First self-applying case + SPEC §3.x promotion (2-case threshold reached) + OTS automation infrastructure

## What's new

### SPEC promotion (§3.x — NEW SPEC section)

**Broad-Verify + Narrow-Execute Combo** — promoted from operational pattern to formal SPEC clause.

- Narrow execution scope + broad verification scope is *structurally required*; symmetric scoping is structurally insufficient to catch scope misspecification
- 2 supporting cases met promotion threshold:
  - v20-a1 Phase 2 (broad grep caught row-cap silent overflow)
  - v21-bootstrap (broad grep caught scope-外 file with leftover placeholder)

### APPENDIX additions (4 patterns, single-case queue)

- **#11 Strategy-Side File Naming Convention Drift** (quirk) — chat artifact naming `/`→`_` collides with canonical repo `/` structure
- **#12 Strict-Superset Reconciliation** (contract) — when candidate A ⊃ canonical B in content, merge A→B then trash A
- **#13 `git add -A` Scope Pollution** (anti-pattern) — explicit FILES + `-A` violates intended scope
- **#14 python-bitcoinlib OpenSSL DLL Dependency** (quirk) — `opentimestamps-client` fails import on Windows/Python 3.14 without OpenSSL

All four await 2nd case for SPEC promotion.

### First self-applying case file

`cases/v21-bootstrap.md` — CCPE deployed via CCPE itself, full round-trip documentation (Phase 1-5, 4 pattern emergences, Option 5 branch-tree extension). Marks lineage transition from "CCPE-as-extracted-from-operations" to "CCPE-as-self-applying-discipline".

### Automation infrastructure

- `scripts/ots-backfill.sh` — OpenTimestamps backfill script (cross-platform, requires OpenSSL)
- `.github/workflows/ots-backfill.yml` — Automated OTS anchoring on push to main (Linux runner, sidesteps #14)

Result: every push to main automatically anchors priority-critical files to Bitcoin blockchain — zero user-environment dependency.

## Why §3.x as a single-section release

This release contains exactly one SPEC promotion (§3.x) and four APPENDIX queue additions (#11-#14). The promotion-vs-queue ratio (1:4) reflects healthy operational evidence intake — most new patterns enter as single-case observations and wait for repetition before promotion. v0.1.5's release-rate (3 promotions from 1 trial) was a cluster-discovery release; v0.1.6 returns to baseline rate.

The §3.x promotion was earned by v21-bootstrap providing the *2nd* case for a pattern v20-a1 had already established. This is the case-driven promotion pipeline working as designed.
